## 1. 프로젝트 개요

### 1.1 목적과 배경

보호자는 서비스 종류뿐 아니라 “우리 부모님이 이용할 수 있는지”, “등급이 없어도 문의할 수 있는지”, “무엇을 준비해야 하는지”를 함께 확인해야 합니다. 블로그에 흩어진 정보를 한 페이지에서 이해하고, 상황에 맞는 안내를 거쳐 상담 채널로 이동하도록 설계했습니다.

| 해결할 문제 | 기획 방향 | 구현 결과 |
| --- | --- | --- |
| 서비스와 이용 절차가 여러 글에 분산됨 | 정보의 우선순위를 정해 한 페이지로 구성 | 서비스·이용 안내·FAQ·위치 통합 |
| 등급 유무에 따라 준비할 내용이 다름 | 이용자의 현재 상태를 기준으로 정보 분기 | 등급 없음 / 등급 있음 선택형 안내 |
| 읽은 뒤 어디로 문의할지 찾기 어려움 | 주요 행동을 상담 연결로 통일 | 첫 화면 상담 CTA, 전화·톡톡 고정 버튼 |
| 새 소식 반영에 반복적인 화면 수정이 필요함 | 콘텐츠 갱신과 웹사이트 배포를 분리 | RSS 수집·JSON 저장·브라우저 갱신 자동화 |

### 1.2 타겟 정의

| 구분 | 상황 및 니즈 | 설계 대응 |
| --- | --- | --- |
| 핵심 고객: 처음 알아보는 보호자 | 제도·등급·준비 서류에 익숙하지 않음 | 쉬운 용어, 등급 없음 안내, FAQ, 전화 상담 |
| 핵심 고객: 등급을 보유한 어르신의 보호자 | 제공 서비스와 방문 일정·지역을 확인하고 싶음 | 등급 있음 안내, 서비스 카드, 상담 연결 |
| 보조 고객: 직접 탐색하는 어르신 | 읽기 쉬운 정보와 단순한 이동을 원함 | 상시 노출 메뉴, 명확한 제목, 큰 상담 버튼 |
| 운영 사용자: 센터 담당자 | 소식을 반복 입력하지 않고 최신 상태를 유지하고 싶음 | 기존 블로그를 소식 원천으로 사용하는 자동 갱신 |

연령·유입 경로·디지털 숙련도는 사용자 조사로 검증하지 않았으며 향후 인터뷰와 방문 데이터로 보완합니다.

### 1.3 프로젝트 범위

- **현재 구현:** 정보 탐색, 상황별 안내, 외부 상담 연결, 지도, 소식 자동 갱신, 기본 검색 메타데이터, 저장소 문서화·정적 검증.
- **현재 범위 밖:** 회원가입·로그인, 사이트 내 상담 접수·예약·결제, 관리자 CMS, 개인별 등급 판정, 비용 계산기.
- **후속 검토:** 실사진과 운영시간 확정, 분석 이벤트 도입, 화면 배포 자동화, 성능·접근성 실측.

**예외 및 운영 규칙**

- RSS 또는 이미지 다운로드 실패 시 기존 JSON을 교체하지 않습니다. 화면의 원격 요청 실패 시 마지막 표시 카드를 유지합니다.
- 카드 안에 키보드 포커스가 있으면 자동 교체를 건너뜁니다.
- 새 글 노출에는 RSS 반영, 예약 실행 대기, 캐시 등으로 지연이 발생할 수 있습니다. 즉시 반영을 보장하지 않습니다.
- 센터의 신청 도움과 공단의 등급 판정을 구분하며, 개별 비용·서비스 가능 일정은 상담으로 확인합니다.

## 4. 핵심 사용자 시나리오

아래 페르소나는 실제 고객 조사 결과가 아닌 설계 검토용 가상 사례입니다.

| Persona | 발단 | 목표 | 진입 | 행동 | 결과 |
| --- | --- | --- | --- | --- | --- |
| A. 부모님의 돌봄을 처음 알아보는 보호자 | 부모님의 일상생활 지원이 필요해짐 | 등급 없이 상담 가능한지 확인 | 검색 또는 공유 링크로 홈 방문 | 서비스 지역 확인 → 이용 안내의 등급 없음 선택 → 준비 항목·FAQ 확인 → 전화 클릭 | 상담 준비 내용을 이해하고 전화 앱으로 이동 |
| B. 등급 인정 후 센터를 비교하는 보호자 | 방문서비스 제공 기관을 찾음 | 필요한 돌봄과 상담 조건 확인 | 센터명 검색 또는 블로그 경유 | 서비스 상세 펼침 → 등급 있음 선택 → 서류·일정 준비 내용 확인 → 톡톡 이동 | 문의할 정보를 정리하고 외부 상담 채널 진입 |
| C. 센터 방문을 준비하는 가족 | 상담을 위해 센터 방문이 필요함 | 정확한 주소와 방문 경로 확보 | 모바일에서 홈페이지 진입 | 오시는 길 선택 → 건물 주소·302호 확인 → 주소 복사 또는 길찾기 → 방문 전 전화 | 주소를 확보하고 방문 일정 확인을 시도 |
| D. 블로그를 운영하는 센터 담당자 | 새로운 센터 소식을 게시함 | 홈페이지에도 최신 소식 노출 | 네이버 블로그에 글 게시 | RSS 반영 → Actions 수집 → JSON·이미지 커밋 → 방문자 페이지 갱신 | 정상 수집 시 홈페이지 수정·재배포 없이 소식 반영 |

시나리오 A~C의 성공은 웹사이트 내 정보 확인과 외부 채널 진입까지입니다. 실제 상담 완료·계약 전환은 별도의 운영 기록으로 확인해야 합니다.

### 6.2 목표 KPI 3가지

아래 수치는 초기 제안입니다. 현재 분석 도구·이벤트 수집은 구현되어 있지 않으며 달성 실적도 없습니다. 측정 도입 후 4주간 기준값을 확보하고 다음 8주를 평가 기간으로 삼습니다.

| KPI | 정의 및 산식 | 제안 목표 | 측정 방법·주의사항 |
| --- | --- | --- | --- |
| 상담 채널 진입률 | 전화 또는 톡톡을 1회 이상 클릭한 세션 ÷ 전체 유효 세션 × 100 | 기준 기간 대비 상대 20% 개선 | `contact_click` 이벤트에 채널·버튼 위치 기록, 세션 중복 제거. 통화·상담 완료율과 구분. 예: 기준 5%이면 목표 6% |
| 이용 안내 후 상담 진입률 | 이용 안내를 확인한 후 상담을 클릭한 세션 ÷ 이용 안내 확인 세션 × 100 | 기준 기간 대비 상대 15% 개선 | 안내 영역 50% 이상이 2초 이상 보이면 확인으로 정의하고 이후 상담 클릭 연결. 실제 이해 여부는 별도 사용자 검증 |
| 블로그 갱신 작업 성공률 | 평가 기간 정상 완료된 예약 실행 수 ÷ 실제 실행된 예약 작업 수 × 100 | 월 99% 이상 | Actions 실행 기록으로 집계. 새 글이 없어도 검증 후 정상 종료하면 성공. 미실행·비활성화는 별도 감시하여 성공률의 사각지대 보완 |

초기 트래픽이 작거나 기준값이 0이면 상대 개선률을 해석하기 어렵습니다. 이 경우 표본 수와 절대 클릭 수를 함께 보고 목표를 재설정합니다. 클릭 이벤트에 이름·연락처·건강정보를 포함하지 않습니다.
