# 배포 및 운영

## 기존 배포 기록

2026-10-06~07 작업 기록을 요약했습니다. 아래는 과거 기록이며 현재 운영 상태를 재검증한 결과는 아닙니다.

- Sites에 정적 웹사이트 게시 후 공개 상태로 전환한 기록이 있습니다.
- Mac mini의 Caddy로 정적 파일을 제공하고 `https://dahamcare.kr`을 연결했습니다.
- Google Search Console 도메인 소유권 확인, 네이버 HTML 태그 소유권 확인과 양쪽 사이트맵 제출 기록이 있습니다.
- 검색엔진 등록은 검색 결과 노출이나 순위를 보장하지 않습니다.

기존 단계별 디자인 변경 기록은 Git 이력에서 확인할 수 있습니다. 현재 구조와 운영에 필요한 내용만 이 문서에 유지합니다.

## 배포 대상

`dist/` 전체를 정적 웹 루트로 제공합니다. 별도 빌드 명령이 없습니다. 기존 `.openai/hosting.json`은 Sites 프로젝트 연결에 사용되므로 유지합니다.

현재 저장소에는 Caddy 설정, DNS 설정, 서버 접속 정보가 없습니다. 따라서 이 저장소만으로 기존 서버 환경 전체를 복원할 수는 없습니다.

## 변경 반영

1. 로컬에서 `python scripts/check_site.py`를 실행합니다.
2. `python -m http.server 4173 --directory dist`로 화면과 인터랙션을 확인합니다.
3. 검토한 변경을 GitHub에 올립니다.
4. 기존 Mac mini의 저장소 사본에서 `git pull --ff-only`로 코드를 갱신합니다. 서버의 실제 문서 루트가 이 사본의 `dist/`인지 확인해야 합니다.
5. 운영 도메인에서 화면·이미지·상담 링크·지도·블로그 표시를 확인합니다.

블로그 데이터는 GitHub Raw에서 별도로 읽으므로 정상적인 자동 갱신에는 서버의 `git pull`이 필요하지 않습니다. 다만 서버의 초기 표시 데이터는 배포 당시 버전으로 남습니다.

## 운영 시 확인할 항목

- Mac mini 전원과 인터넷 연결, Caddy 프로세스 및 TLS 인증서 상태
- Actions의 최근 실행 결과와 `dist/blog/posts.json` 갱신 여부
- 도메인 변경 시 canonical·구조화 데이터·robots.txt·sitemap.xml 수정
- 저장소 이름 변경 시 `dist/script.js`의 GitHub Raw 경로와 관련 문서 수정

## 후속 개선

- 실제 서버 설정을 민감정보 없이 재현 가능한 형태로 문서화
- 화면 배포 자동화 및 배포 실패 시 복구 절차 추가
- 실제 화면 캡처와 측정 조건을 포함한 성능·접근성 결과 추가
- 게시 동의된 센터 사진, 운영시간, 서비스 가능 일정 확인
